# 오늘 학습한 내용

## SDD에서 명세와 구현의 추적성

SDD는 명세를 기준으로 설계하고 구현하는 개발 방식이다. 사용자 스토리, FR, API, 데이터 모델과 테스트가 연결되어야 기능이 왜 필요한지와 무엇을 검증해야 하는지 설명할 수 있다.

일정이 짧아져도 이 연결을 없애지 않는다. 이번에 구현할 사용자 흐름에 필요한 명세와 미결정 사항부터 검토하고 작은 단위로 설계·구현·검증을 이어 간다.

## MVP Scope와 단기 구현 범위

MVP Scope는 제품 가설을 검증하기 위해 승인한 전체 범위이고, 단기 구현 범위는 특정 기한까지 먼저 완성할 대상을 정한 것이다.

두 범위를 구분하면 일부 기능을 먼저 시연하더라도 원래 MVP 전체가 완료된 것처럼 설명하지 않을 수 있다.

## 범위 축소와 요구사항 삭제

웨이트나 닉네임 수정을 이번 구현에서 유예해도 기존 Must 요구사항 자체가 사라지는 것은 아니다. 요구사항과 ID를 보존하고 이번 구현에 포함하지 않는 부분을 별도 문서에 남겨야 후속 작업과 테스트를 추적할 수 있다.

## Vertical Slice로 사용자 흐름 연결하기

Vertical Slice는 하나의 사용자 행동이 화면, API, 비즈니스 규칙, 저장과 조회까지 이어지도록 작은 흐름 단위로 개발하는 방식이다.

예를 들어 일반 입력으로 운동 기록을 저장하고 다시 조회하는 흐름을 먼저 연결한 뒤 자연어 구조화와 계획 반영을 추가할 수 있다. 매 단계에서 실제 사용자 흐름을 검증하여 통합 문제를 일찍 발견하는 데 도움이 된다.

## Human-in-the-loop와 규칙 기반 추천의 책임

AI는 자연어 운동 결과를 구조화하지만 사용자 확인 없이 최종 기록으로 저장하지 않는다. 사용자는 결과를 확인하고 수정한 뒤 저장을 확정한다.

운동 계획의 핵심 내용은 규칙이 결정하고 AI는 해석과 설명을 돕는다. 계획 후보의 수정·확정·거절과 운동 세션 시작도 분리하여 사용자의 최종 결정권을 유지한다.

# AI Love Workout에 적용한 내용

* 러닝과 맨몸운동을 1차 구현 대상으로 정하고 웨이트 및 일부 기능은 후속 구현으로 유예한다.
* 기존 APPROVED 요구사항은 보존하고 별도 1차 구현 범위 문서에 포함·유예 대상과 완료 기준을 기록한다.
* 자연어 운동 기록 → 사용자 확인·수정 → 저장 → 다음 운동 계획 반영이라는 핵심 가치를 유지한다.
* 일반 입력 기록 저장·조회 흐름부터 연결하고 계획과 AI 기능을 통합하는 작업 순서를 따른다.
* 기록 저장에는 진행 중인 세션이 필요하며 빈 세션 종료 확인과 미완료 입력 보호 정책을 유지한다.
* 명세·설계·테스트 추적성과 리뷰 원칙을 유지한다. 누락 FR 검토, 최소 도메인 설계와 환경 구축은 이어서 진행할 작업이다.
* 인증 토큰, 운동 규칙, 기록 단위와 초안 보존 등 미결정 정책은 임의로 확정하지 않는다.
