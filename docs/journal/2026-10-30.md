# 2026-10-30 개발 일기

오늘은 집 PC에서 AI Love Workout 작업을 재개했다. SourceTree에서 main과 origin/main이 동일한 최신 커밋 e913eaa를 가리키는 것을 확인했다. 이 커밋은 10월 28일 개발 기록 보완 내용이며 Commit & Push까지 완료된 상태다.

작업 시작 전 미커밋 변경 사항이 없는 것을 확인하고 Study / Meeting / Journal 작업 시작 문서를 생성했다. 앞서 React + Spring Boot + FastAPI + PostgreSQL 기반 개발 환경을 구축했으며, 오늘은 SDD 방식을 유지하면서 AUTH + USER 정책 확정과 실제 기능 구현을 진행했다.

먼저 회원가입 후 별도 로그인, 30분 Access Token과 Refresh Token 미사용, PostgreSQL 기반 jti 무효화, 운동 프로필 허용값과 최초 설정·부분 수정 정책을 결정했다. 승인 내용을 문서에 반영한 뒤 Codex로 Spring Boot·PostgreSQL·React 기능을 연결했다. 계정 조회와 본인 데이터 접근 제한도 구현했으며 초기 자동 테스트 47개와 React 타입 검사·빌드가 통과했다. Compose 서비스 연결, 실제 DB 저장과 서버 재시작 후 로그아웃 무효화 유지도 확인했다.

Chrome에서 회원가입 후 로그인 화면 전환과 로그인, 운동 프로필 최초 설정·저장·조회, 수정 화면 진입과 변경 없이 저장 시 안내, 로그아웃 후 로그인 화면 표시를 직접 확인했다. 로그아웃 이전 JWT로 보호 API를 다시 요청하면 401이 반환되고, 브라우저를 새로고침하면 다시 로그인해야 하는 것도 확인했다.

이후 Codex의 읽기 전용 보안 감사에서 필수 문제 두 건을 발견했다. 짝이 없는 UTF-16 surrogate가 UTF-8 변환 중 다른 문자로 치환되어 서로 다른 비밀번호가 같은 해시에 일치하는 문제와, 백엔드가 허용하는 Unicode 이메일을 브라우저의 type=email이 차단하는 문제였다. 잘못된 Unicode를 가입·로그인에서 400으로 거부하고 해싱 단계에서도 치환을 막았으며, 이메일 입력은 서버 검증 기준과 맞췄다. 정상 Unicode와 기존 비밀번호 해시 형식은 유지하고 관련 회귀 테스트를 추가했다.

필수 수정 후 첫 전체 회귀 실행에서는 기존 프로필 테스트 16개가 사전 회원가입 단계의 DB 503으로 실패했다. 환경 연결 상태를 확인한 뒤 추가 코드 변경 없이 같은 코드로 재실행했고, PostgreSQL 통합 38개를 포함한 총 82개가 모두 통과했다. 최초 실패 원인은 확정하지 않았다. React 타입 검사·빌드와 Docker 서비스 빌드도 성공했으며, Edge headless에서는 ASCII·Unicode 이메일의 실제 폼 제출부터 프로필 설정·변경·재조회·재로그인·로그아웃까지 각각 확인했다. 실제 프로필 값 변경 후 재조회의 Chrome 수동 검증 여부는 아직 확인되지 않았다.

마지막으로 UI/UX 개선 방향을 논의했다. Deep Green + Warm Ivory 기반의 운동 데이터 중심 UI를 지향하고, 디자인 시스템의 기준을 먼저 정해 기능 개발과 병행한 뒤 마지막에 전체 완성도를 개선하기로 했다. 테스트 통과와 실제 화면 검증은 서로 보완해야 하고, 실패 결과도 원인을 단정하지 않은 채 기록해야 한다는 점을 배웠다.

오늘 AUTH + USER 작업의 Commit/Push는 아직 수행하지 않았다. 다음 작업은 SESSION + RECORD의 정책·명세 검토와 구현이다. PLAN·NLP 구현, HTTPS 배포와 HMAC pepper 등 운영 보안 검토도 후속 작업으로 남아 있다.
