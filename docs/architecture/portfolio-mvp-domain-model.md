# 포트폴리오 MVP 최소 도메인 모델

* 작성일: 2026-10-28
* 범위: 러닝·맨몸운동 1차 MVP의 구현 출발점
* 상태: 최소 설계. 기존 승인 요구사항의 변경이나 기능 구현 완료를 의미하지 않음

## 도메인과 관계

| 도메인 | 책임과 최소 데이터 | 관계 |
| --- | --- | --- |
| User | 계정 식별자, 이메일, 보호된 비밀번호, 닉네임, 사용자 시간대 | 프로필 0..1개, 후보·확정 계획·세션 여러 개의 소유자 |
| WorkoutProfile | 운동 목표, 경험 수준, 주요 운동 유형, 사용 가능한 장비 | User에 종속. 최초 설정 전에는 존재하지 않을 수 있음 |
| WorkoutPlanCandidate | 생성 조건, 운동 항목·수행값·시간 배분, 최초 추천 이유, 소유자 | User 소유. 하나의 후보에서 확정 계획은 최대 한 개 |
| ConfirmedWorkoutPlan | 사용자가 확정한 후보의 현재 수행 내용과 시간 정보 스냅샷 | 원본 후보를 식별하며 후보 편집과 독립된 확정 결과 |
| WorkoutSession | 시작·종료 시각, 진행·종료 여부와 기록 유무 | User 소유. 확정 계획 연결은 선택적이며 기록은 0..N개 |
| ExerciseRecord | 실제 수행한 러닝 또는 맨몸운동 데이터와 운동 일시 | 반드시 한 세션에 소속. 계획을 그대로 복사해 실제 수행으로 간주하지 않음 |

러닝은 거리·운동 시간·계산된 평균 페이스, 맨몸운동은 종목·반복 횟수 또는 수행 시간·세트 수를 가진다. 값의 단위와 허용 범위, 여러 입력의 병합 단위는 상세 명세 검토 전 확정하지 않는다. 계획의 항목과 수행 기록은 서로 다른 값 객체·데이터로 표현한다.

## 유지하는 규칙

* User → WorkoutProfile 최초 설정·부분 수정은 FR-USER-003~004를 따른다. 미설정 프로필을 임의 기본값으로 저장하지 않는다.
* 후보 생성의 핵심 내용은 규칙으로 결정한다(FR-PLAN-001~004). 최근 기록이 없을 때도 기본 정보를 이용한다.
* Current/Previous는 후보의 역할이며 생명주기 상태와 구분한다. 조작 가능한 현재 후보는 사용자당 하나이다. 신규 생성 시 기존 후보 교체의 세부 정책은 구현 전에 확인한다.
* 후보 편집은 원자적으로 수행하고 자동 확정·세션 시작을 하지 않는다. 반복 확정은 실패하며 확정 시점의 현재 내용을 보존한다(FR-PLAN-005~007, ADR-004).
* 후보 수정 후 최초 추천 이유는 최초 생성 당시 설명으로 유지한다. 확정 계획에 추천 이유를 보존할지는 미결정이다.
* 계획 유무와 관계없이 사용자의 별도 시작 동작으로 세션을 생성한다. 확정 계획의 재사용 가능 횟수는 이 설계에서 결정하지 않는다.
* 진행 중 세션은 사용자당 하나로 제한하고 기록 저장 시 소유권과 진행 상태를 확인한다(US-04-01~05, US-05-02~03).
* 빈 세션은 확인 후 종료하고 통계·추천용 최근 기록에서 제외한다. 종료 취소는 CANCELLED 상태 생성이 아니다(US-04-06, US-06-07).
* 서버 시각은 UTC, 사용자 시간대는 별도 관리한다. 모든 도메인의 접근은 인증된 소유자 기준이다.

## 자연어 구조화 경계

`자연어 → FastAPI 구조화 응답 DTO → 사용자 확인·수정 → Spring Boot 기록 저장`으로 분리한다. 확인 전 DTO는 ExerciseRecord가 아니며 파싱 요청 자체로 최종 기록을 저장하지 않는다(ADR-001, US-06-01~07).

원문·미완료 결과의 임시 보관 위치, 기간, 재접속·인증 만료 시 복원은 미결정이다. 이번 골격에는 DTO 저장소나 초안 테이블을 만들지 않는다. 이는 향후 초안 보존을 금지한다는 결정이 아니다.

## 비즈니스 구현 전에 해소할 공백

| 영역 | 확인할 정책 | 근거 |
| --- | --- | --- |
| SESSION | 미종료 세션 자동 처리, 빈 종료 세션 노출, 미완료 입력과 종료 확인의 순서·요청 계약 | US-04-01~06, US-06-07 |
| RECORD | 운동 종목·단위·허용값, 세트 사이 입력의 병합·저장 단위, 종료 후 수정·삭제 범위, 마지막 기록 삭제 후 빈 세션 처리, 삭제 방식 | US-05-02~05 |
| NLP | 누락·불명확한 값 처리, 복수 결과 저장의 원자성, 초안 보존·폐기·인증 만료 정책 | US-06-01~07 |
| HISTORY | 사용자 시간대의 날짜 경계·자정 걸친 세션 분류, 정렬·페이지 처리, 진행·빈 종료 세션 노출 | US-07-01~03 |

SESSION·RECORD·NLP·HISTORY의 상세 FR은 미작성 상태다. 위 공백은 골격 구축을 막지 않으나 관련 비즈니스 API·DB 구현 전에 명세화해야 한다. 인증 토큰 운영 정책, 지원 프로필 값, 최근 기록 기간과 계획 산정 규칙도 별도 결정 대상이다.
